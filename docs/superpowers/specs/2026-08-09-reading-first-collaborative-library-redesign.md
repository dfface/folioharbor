# 阅读优先的协作书库重构设计

## 决策

FolioHarbor 从后台式目录改为阅读优先的单页应用。当前书库是
稳定的产品上下文；个人书库、家庭书库和团队书库使用同一界面。
首页同时承担继续阅读、个人阅读记录、书库馆藏和协作感知四种
职责，而不是将它们拆成互相跳转的页面。

项目仍处于开发期，因此替换现有 HTTP API 和前端路由契约，不保
留 `/v2` 前缀、旧端点或兼容适配层。保留数据库中以 Library 为协
作与隔离边界、阅读状态属于个人、授权由服务端强制执行的领域约束。

## 目标用户与产品原则

- **用户**：个人阅读者，以及使用家庭或小团队共享书库的成员。
- **首要任务**：从当前书库快速回到正在阅读的内容，并自然发现已
  读、未开始和馆藏中的其他书。
- **协作原则**：共享的是书库和其成员关系，不是阅读位置。成员、
  上传和邀请可见，但不应夺走正文阅读的注意力。
- **视觉与交互气质**：柔和、沉浸、书籍优先；操作清晰但不呈现为
  管理后台。
- **安全原则**：界面投影只展示服务端已经授权的事实；阅读、下载、
  上传和成员管理仍是不同能力。

## 信息架构

桌面端使用持久书库侧栏；移动端将它收敛为底部导航和书库切换器。
侧栏只承担稳定的空间切换，不放阅读器控制。

```text
当前书库
├── 首页
│   ├── 继续阅读
│   ├── 在读
│   ├── 读过
│   ├── 未开始 / 想读
│   ├── 书库馆藏
│   └── 协作动态（成员、导入完成、邀请）
├── 书架
│   ├── 全部
│   ├── 在读
│   ├── 读过
│   └── 未开始 / 想读
├── 导入（具备编辑能力时）
├── 成员（具备管理能力时）
└── 书库设置（具备管理能力时）
```

首页不是全实例“全部图书”。它始终属于当前 Library。个人阅读状态
以用户和 Item 为范围保存，因而相同的共享书可以为不同成员显示不
同的在读、读过和位置状态。

## 首页与书架

### 首页

1. 顶部显示当前书库名称、书库类型与切换入口。
2. `继续阅读` 是首个内容区：有进度的书按最后阅读时间排序；每本书
   提供明确的继续阅读动作和当前位置。
3. `在读`、`读过`、`未开始 / 想读` 是独立横向书架。它们描述当前
   用户在当前书库中的阅读关系，不伪装成书库全体成员的共同状态。
4. `书库馆藏` 提供可浏览的完整集合、搜索和筛选入口。
5. 协作动态位于宽屏辅助栏、窄屏次级区：只呈现已授权且对理解书库
   有帮助的事件，例如成员加入、导入完成和邀请状态。它不展示他人
   的阅读位置或正文内容。

### 书架与详情

书架页专注浏览与管理：封面网格、紧凑列表、搜索、状态筛选与导入。
书籍详情提供封面、书目资料、当前用户的阅读状态、阅读/下载能力和
协作相关但不泄露隐私的馆藏信息。阅读状态可在详情或书架的轻量菜单
中切换；状态修改立即更新当前用户的首页投影。

## 阅读器

阅读器从应用壳中退出为沉浸式工作区：正文占据主要视口，默认隐藏
多余导航。目录、字体、行距、主题、阅读进度和章节跳转以按需抽屉或
短暂工具栏呈现。键盘、触摸和点击都能完成前后章节与控制显隐。

阅读器初始化必须返回当前用户的进度、可读能力、目录与显示偏好；
正文资源继续在受限 iframe 中加载。离开、章节切换和定时同步只更新
当前用户的 Reading State。被移除成员的下一次资源请求必须立即被拒绝。

## API 契约重构

现有 OpenAPI 描述和 HTTP handlers 直接替换为面向产品界面的资源。
不发布 `/v2`，不维护旧 schema 或旧前端适配层。

### 聚合读取

- `GET /api/libraries`：返回用户可访问的书库及能力，用于切换器。
- `GET /api/libraries/{library_id}/home`：返回首页投影：继续阅读、三类
  个人书架预览、书库摘要、已授权协作动态与可执行能力。
- `GET /api/libraries/{library_id}/shelf`：接受稳定的状态、搜索、排序
  和分页参数，返回书架结果及当前用户针对每本书的阅读投影。
- `GET /api/libraries/{library_id}/books/{item_id}`：返回阅读、下载、编辑
  和成员可见性已计算完成的书籍详情。
- `GET /api/libraries/{library_id}/activity`：返回经过权限与隐私过滤的
  协作事件；不包含他人的阅读位置。
- `GET /api/libraries/{library_id}/books/{item_id}/reader`：返回阅读会话，
  包括目录、进度、显示偏好、阅读能力和安全资源定位所需的元数据。

### 个人阅读写入

- `PATCH /api/libraries/{library_id}/books/{item_id}/reading-state`：更新
  `unstarted`、`reading`、`finished`、`want_to_read` 等个人状态与可选
  书签/位置。
- `PUT /api/libraries/{library_id}/books/{item_id}/progress`：同步 Readium
  Locator 与客户端版本，用于跨设备冲突处理。
- `PATCH /api/me/reader-preferences`：保存与书库无关的阅读显示偏好。

### 协作与导入

成员、邀请、角色、书库设置和上传保持清晰的命令式资源边界，但路由
命名、响应结构和 problem code 与上述资源统一。服务端继续从授权服务
计算 capability，客户端不得用角色名自行推导权限。

## 应用和存储边界

新增面向读取的应用投影服务：Home、Shelf、Activity、Reader Session。
它们从现有 Library、Catalog、Membership、Reading Progress 和审计事件
读取，并在应用层按授权事实组装；不会把全局目录、Blob、文件路径或
其他书库的元数据暴露到 transport 层。

个人书架状态需要明确的持久模型（用户、Library、Item、状态、排序
时间、完成时间与可选定位）。协作动态使用审计事件的受限投影，而不
把审计表直接暴露为 API。数据库迁移可以重塑仍处开发期的表与约束，
但必须保留 RLS、最后一位 owner、不跨 Library 泄露和 Blob 生命周期
的安全不变量。

## 前端边界

前端保留 feature 目录的可测试边界，但以以下产品域重组：

- `app-shell`：书库选择、桌面侧栏、移动导航、会话入口。
- `home`：首页投影与继续阅读。
- `shelf`：浏览、筛选、书籍卡片与状态控制。
- `reader`：沉浸式阅读工作区、目录、显示设置和同步。
- `collaboration`：成员、邀请、活动与书库设置。

所有交互组件必须包含默认、悬停、焦点、按下、禁用、加载、错误和成
功状态。移动端在 320、375、414 和 768 CSS 像素宽度下无横向滚动，
且主要操作始终可触达。

## 迁移与删除策略

1. 先定义新 OpenAPI 和应用投影，再让前端按新契约实现。
2. 以可重建的迁移替换未发布的旧 transport schema 与前端 generated
   client；不保留旧 API handler、旧路由或双写逻辑。
3. 删除只限于被新功能完整替代的旧页面、端点和测试；每个删除会在
   实施计划中逐文件列出，并在删除前得到确认。
4. 每个阶段都验证权限、个人阅读隔离、EPUB 资源 sandbox、上传状态
   机和跨设备进度。

## 验收标准

- 用户打开任一书库，先看到可继续阅读的内容和自己的阅读过的书。
- 书架、读过状态和进度随书库切换而改变；共享成员不会共享阅读位置。
- owner、editor、reader 看到的导入、成员、下载和设置能力正确且由服
  务端强制。
- 阅读器在桌面与手机上保持正文优先，目录和设置不破坏阅读连续性。
- API 和前端不存在旧接口兼容层；生成客户端与 OpenAPI 一致。
- 所有资源访问仍经过 Library 授权与 RLS，且撤销成员后立即失去读取
  权限。
