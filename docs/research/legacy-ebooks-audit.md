# 旧 ebooks-go 数据调研摘要

状态：已完成初步只读调研

调研日期：2026-08-04

数据源：本机 PostgreSQL `127.0.0.1:5434`，数据库 `ebooks`，Schema `ebooks`

完整线上报告：[数据治理与私人图书馆产品调研（2026-08-04）](https://outline.yuhan.tech/doc/2026-08-04-50X1BpMBKF)

## 数据规模

| 对象 | 数量或大小 |
| --- | ---: |
| `book` | 39,108 行，约 422 MB |
| `chapter` | 5,134,239 行，约 25 GB |
| `annotations` | 3 行 |
| 含 `redirect_chapter_id` 的章节 | 2,661,748 行，约占 51.8% |

## 已验证事实

- 所有已检查的章节重定向都指向同一本书中的后续章节。
- 未发现缺失目标、自重定向或向前一章回退的重定向。
- `chapter(book_id, chapter_id)` 存在唯一索引，`chapter.id` 是主键。
- 未发现孤立的 chapter 行，但数据库没有强制 chapter 到 book 的外键。
- 有 18 本书的 `book.total` 与实际章节数不一致，最大差值为 769。
- 有 38 本书没有章节。
- 旧程序依赖 `(book_id, chapter_id)` 和 HTTP 302 重定向继续阅读。
- 只有 Annotation 使用了 AutoMigrate，book 和 chapter 没有完整的版本化迁移体系。

## 章节冗余的当前结论

业务判断是：部分后续章节完整包含前面章节的可见正文，因此治理时应保留后续章节，而不是继续保留重定向补丁。

数据库原始 HTML 的直接相等和直接子串检查不能证明这一点：重定向源与目标的原始 HTML 相等数为 0，直接子串包含数也为 0。这说明删除前必须使用与阅读器一致的正文规范化流程，去除模板、样式和标记差异后，再执行“后章完整包含前章”的语义验证。

## 对新项目的约束

- 新项目不能继承 redirect 作为正常内容模型。
- 旧数据库只读保留，迁移程序从中抽取、规范化、验证并写入新数据库。
- 去重判定必须产出可审计证据和映射，不能直接批量删除原数据。
- 旧 HTML 的清理、打包和压缩放在迁移阶段处理，不影响第一版 EPUB、TXT、PDF 模型。
- 新项目的数据库必须从空库通过显式版本化迁移完整创建。
