# 产品愿景与范围

状态：讨论草案

更新时间：2026-08-05

## 愿景

FolioHarbor 是一个可由个人或组织自行部署的数字图书馆。用户可以保存自己合法持有的电子出版物，在多个设备上阅读，并在明确授权的书库内协作、整理和分享。

长期目标是让相互独立的私人图书馆在保持数据主权的前提下建立社区：发现作品、关注读者、发布书评和书单，但不默认传播受保护的书籍文件或私人阅读数据。

## 第一版必须解决的问题

### 身份与实例

- 一个实例支持多个用户。
- 同时支持本地账户和 OIDC SSO。
- 是否允许公开注册由实例管理员配置，默认允许。
- 是否要求邮箱验证由实例管理员配置，默认要求。
- 支持注册频率限制、邀请限制和允许的身份域规则。

### 书库与协作

- `Library（书库）` 是唯一的协作、数据隔离和权限边界，不再引入语义重叠的 Workspace。
- 一个用户可以加入多个书库。
- 私人书库与共享书库采用同一模型。
- 内置 `owner`、`editor`、`reader` 角色，并以独立权限项表达能力，为后续自定义角色留出兼容空间。
- 支持资源级可见性与授权：私人、书库可见、受限授权、公开。
- 个人阅读进度和批注默认仅本人可见。

### 内容与阅读

- 首批导入并阅读 EPUB、TXT 和 PDF。
- 保留不可变原文件，用于重新处理、导出和客户端下载。
- Web 阅读器按受控资源接口读取出版物，不永久解包 EPUB。
- Android 客户端未来按整本原文件下载，支持断点续传、内容哈希和版本识别，而不是逐章下载。
- 支持元数据搜索；全文搜索可按书库启用 Meilisearch。

### 存储与数据

- 必须支持本地文件系统和 S3 兼容对象存储。
- EPUB 和 PDF 不做应用层重复压缩。
- 相同字节可按 SHA-256 去重，但书目、馆藏、权限和来源不得因物理去重而合并。
- PostgreSQL 是业务事实源；全文索引和衍生缓存必须可以重建。
- 数据库变更采用显式、带版本号的迁移，不采用根据模型猜测结构的 AutoMigrate。

## 长期方向，不属于第一交付闭环

- Android 原生客户端。
- 漫画、有声书以及更多文档格式。
- 基于 ActivityPub 的关注、书评、书单和推荐动态。
- 基于 OPDS 2.0 的公共或授权目录。
- 可作为普通联邦节点接入的中心评价站点，例如网文评价社区。
- 旧 `ebooks-go` 数据经过治理后迁移。

## 明确的非目标

- 第一版不采用微服务、Kafka 或复杂分布式基础设施。
- 不把书籍文件、私人书架、进度和私人批注默认发布到联邦网络。
- 不为了全文搜索永久保存 EPUB 的第二份解包副本。
- 不把旧数据库结构兼容性带入新核心模型。
- 不在产品设计完成前开始旧数据迁移。

## 仍需逐项确认

- 新用户注册成功后是否自动创建个人书库，以及通过邀请注册时的行为。
- 第一版是否允许创建自定义角色，还是只保留兼容的数据模型。
- 书库、用户和实例级存储配额与超限行为。
- 公开书目页与公开下载之间的默认关系。
- 内容导入失败、重复上传和格式不完整时的用户体验。
- 第一条可独立实施的产品纵切范围与验收标准。
